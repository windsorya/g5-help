**3. 可直接實作的規格**

修改範圍限 `src/app.html` 的查詢、撤回及清單呈現，以及 `tests/e2e.py` 的相應測試。

**狀態**

```js
MINE_EPOCH = 0;               // 撤回確認成功才遞增
MINE_SEQ = 0;                 // 全頁遞增，不歸零
MINE_APPLIED = 0;             // 本世代最後成功套用的查詢序號
MINE_PENDING = new Map();     // seq -> request
WITHDRAWN_IDS = new Set();    // 本頁已確認撤回的 ID
WD_PENDING = null;            // 撤回中的操作；同時最多一筆

MINE_TIMEOUT_MS = 90000;
WITHDRAW_TIMEOUT_MS = 90000;
```

每個查詢紀錄包含：

```js
{ seq, epoch, controller, timer, deadline, closed: false }
```

上述狀態限定目前家庭碼；請求須捕捉發送時的家庭碼，回應若已不屬目前家庭碼不得採用，撤回集合也不得跨家庭碼套用。

**查詢發送與結束**

1. `loadMine(true)` 只在 **`MINE_PENDING` 中存在目前世代、尚未結束的查詢**時略過。舊世代請求不參與判斷。
2. 手動展開清單、撤回成功後的 `loadMine()` 可另發查詢；**新查詢不改世代，也不中止同世代較早查詢**。因此 W10 的 A、B 可以同時在途。
3. 每個請求發送時固定自己的 `seq`、`epoch`、截止時間；期限涵蓋 fetch、本文讀取與 JSON 解析。
4. 成功、HTTP 錯誤、JSON 錯誤、`ok:false`、網路失敗及逾時，全走同一個 `finish(request, outcome)`：
   - 若已 `closed`，立即返回。
   - 標記 `closed`、清除 timer、**只刪除這筆 `seq`**。
   - 再判斷是否允許改畫面。
   - 舊世代的結束只清自己的紀錄，不能清除新世代請求或提示。
5. 成功回應的採用條件為：

```text
未逾時
且發出時的世代＝目前世代
且 seq > MINE_APPLIED
且 HTTP、JSON、ok 與 items 結構有效
```

符合才更新 `MINE_APPLIED`、`LAST` 及画面；採用前濾掉 `status === "withdrawn"` 和 `WITHDRAWN_IDS` 內的題目。**禁止改回 `seq === MINE_SEQ`。**

6. 查詢失敗保留 `LAST`，顯示「進度暫時讀不到，稍後再看。」；**失敗不推進 `MINE_APPLIED`**。較晚發的 B 失敗後，仍允許尚未被成功回應超越的 A 提供有效資料。已被較新成功回應超越的舊錯誤不得覆蓋提示。

**逾時與輪詢**

- 設計採 **90 秒**：高於既有 **65 秒**反例，也容許查詢跨過一次 **60 秒**輪詢，而不被新一輪取代。這是設計值，**不是實測 GAS 延遲**。
- 逾時先透過 `finish` 釋放邏輯狀態，再 `controller.abort()`；不等待 abort 的 rejection 才釋放。
- 回應入口與發送前也檢查截止時間，避免 timer 延遲執行時仍採用過期回應。
- 逾時後不立即無限重試，由下一次輪詢或手動展開重試。前景正常計時下，t=0 卡住的查詢於 t=90 秒釋放，t=120 秒輪詢可再發。
- 清單收起時輪詢不發送；**收起不換世代、不清空快取**。重新打開立即顯示快取並手動查詢一次。
- 背景分頁或裝置睡眠可能延遲計時器；90 秒不是瀏覽器停擺期間的硬性完成保證。

**撤回**

1. 送出時建立 `WD_PENDING`，清除確認倒數；所有撤回按鈕暫時禁用，事件處理器也檢查 `WD_PENDING`。任何查詢重畫都必須保留禁用狀態，不能只禁用已被替換的舊 DOM 按鈕。
2. 只有收到有效 `ok:true`，才依序：
   - 將目標 ID 加入 `WITHDRAWN_IDS`。
   - `MINE_EPOCH++`，`MINE_APPLIED = 0`。
   - 從 `LAST.items` 移除目標並**立即重畫**。
   - 清除撤回中狀態、顯示成功訊息。
   - 清單開啟時立即發一筆新世代查詢。
3. 舊查詢可以留到自己的期限；它既不能改畫面，也不能阻擋新世代輪詢。**不把「舊網路請求是否真的中止」當作正確性的前提。**
4. 明確 `ok:false` 不換世代、不加入撤回集合、不移除題目；顯示原因並恢復操作。
5. 網路失敗或撤回逾時也不本機移除；顯示「撤回結果尚未確認，請重新查詢。」並允許重查。**不自動重送撤回 POST**，因為中止等待不代表伺服器未執行。已結束操作的遲到 callback 不再更新狀態。
6. 第一筆撤回完成後，即使其刷新查詢仍在途，也允許撤回第二筆；第二次成功再換世代。確認操作仍保留原有 5 秒取消機制。

另在 `.hcard` 加穩定的 `data-mine-id`，讓已完成、已無撤回按鈕的題目仍可精確定位。

**4. 有限驗收矩陣**

各案例使用獨立 page/context 與假資料。以 `page.route` 攔截 `op=mine/withdraw`，在攔截當下保存快照；以 `page.clock` 或擷取的清單輪詢 callback 控制時間。不得連到正式 GAS。

記號：A、B、C 為查詢；X 為撤回目標；Y 為另一筆題目。

| 案例 | 操作序列 | 預期畫面與必要證據 |
|---|---|---|
| 1．R1／W9：舊成功晚到 | 先顯示 X、Y → 扣住舊 A → 撤回 X 成功 → 扣住新 B → 放行含 X 的 A；另跑 A 在 B 完成後才放行的排列 | **撤回成功當下 X 就消失**；兩種排列均不得重現 X 或其撤回按鈕 |
| 2．R2：每次延遲 65 秒 | t=0 扣住 A → t=60 執行輪詢 → t=65 放行 A；下一輪再重複 | t=60 不疊發；A 的目標狀態更新成功；後續仍能更新，不能永遠停在舊清單 |
| 3．W10：A 先完成 | 初始目標 `u4-4` 製作中、另一題已做好 → 手動發 A、B 並都扣住 → **確認兩者仍在途** → 只放行 A，內容使 `u4-4` 完成 | **B 未放行前**，`u4-4` 的卡片已有完成連結、正確 href，且無撤回按鈕 |
| 4．同世代反序完成 | 扣住 A、B → 先放行較新的 B，目標完成 → 再放行 A 的製作中快照 | 目標保持完成；再以 A 網路失敗的排列測試，健康提示也不得被舊錯誤覆蓋 |
| 5．R3：舊世代永不返回 | 扣住 A → 撤回 X 成功 → 新 B 正常完成 → **不處理 A**，連做 5 次「輪詢 callback → 放行該次新查詢」 | 每次均確實發出新查詢，Y 的狀態按回應更新；不必等 A 結束 |
| 6．目前世代永不返回 | 扣住 A → 推進至 60 秒、90 秒、120 秒 → 放行 120 秒的新查詢 | 60 秒不疊發；90 秒顯示讀取失敗但保留清單；120 秒能重查並更新 |
| 7．舊請求清理不影響新請求 | 舊 A 尚未到期 → 撤回成功後扣住新 B → 讓 A 到期或中止 → 呼叫輪詢；之後放行 B 再呼叫一次 | B 尚在途時不疊發；B 結束後恢復發送，不能因 A 清理而誤認 B 已結束 |
| 8．查詢失敗 | 分別令目前查詢 `route.abort()`、HTTP 500、非法 JSON、`ok:false` → 下一輪成功 | 保留原卡片及操作；顯示讀取失敗；下一輪能恢复並更新 |
| 9．較新失敗、較舊成功 | 扣住 A、B → B 失敗 → A 回傳有效新狀態 | A 仍可更新目標並清除讀取失敗提示；錯誤不能成為阻擋 A 的序號 |
| 10．撤回明確失敗 | 撤回分別回 `done`、`not-found`、一般 `ok:false` | 不本機移除、不顯示成功、不留下禁用狀態；`done` 顯示不能撤回，後續成功重查可更新實際狀態 |
| 11．撤回網路失敗／永不返回 | 撤回 `route.abort()`；另跑扣住至 90 秒，再模擬遲到成功 | 未確認前保留題目，顯示結果未確認；恢復操作；不自動多送 POST；遲到 callback 不冒出成功訊息 |
| 12．連續撤回兩筆 | 扣住撤回 X → 嘗試撤回 Y → 放行 X 成功並扣住其刷新 B → 撤回 Y 成功 → 放行仍含 Y 的舊 B → 完成最新查詢 | X 未完成時不多送撤回；之後 Y 可正常撤回。兩筆各自成功即消失，B 不讓 Y 重現，其他題目仍能輪詢 |
| 13．清單收起再打開 | 扣住 A → 收起 → 執行輪詢 callback → 展開並扣住 B → 依序或反序放行 | 收起期間無新輪詢；展開立即看到快取並確實發 B；A、B 遵守採用順序與各自期限 |
| 14．撤回後重查失敗或含舊資料 | 撤回 X 成功 → 新 B 失敗；另跑 B 成功但仍含 X | X 均保持消失；失敗只影響健康提示；成功回應仍能更新 Y，不能整份丟棄 |

案例 5 的五次 callback 可在 A 期限前直接呼叫；**每次先完成新世代查詢再呼叫下一次**，避免把正確的「目前世代不疊發」誤判成阻塞。
