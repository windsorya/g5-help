# upload.js 清單生命週期：Codex 設計者結論（2026-10-13 21:3x，升級階梯：8601526→954df2a→1a9b918 連 3 輪 FAIL）

審的對象：docs/upload-list-lifecycle-design-20261013.md（我依難題站 99b8394 設計者選項 B 改寫的版本）。以下為設計者回覆原文整理。

## (a) 我的設計漏掉的路徑（需把撤回、照片上傳與 DOM 所有權一起納入生命週期）
- stop／重掛仍可能被上傳回呼破壞：第一張上傳扣住→stop→重掛並填新草稿→放行舊上傳，第二張仍向舊家庭送出，最後清掉新元件草稿。stop 必須涵蓋縮圖、逐張送出、解鎖與清空輸入；每個容器只能有一個有效 owner。（src/upload.js:105、165–182）
- 撤回不能只比較家庭碼字串：A 題目已確認、換 B 但尚未跑兩秒檢查時，會送出 {code:B,id:A的題目}；A→B→A 時舊操作可能再次符合「家庭碼未變」。須捕捉 familyRevision＋operationId；確認、送出、回應入口都核對；舊操作只能釋放自己的鎖。（src/upload.js:122–136）
- 查詢入口要明確：familyCheck() 只更新／失效狀態、不發請求，由唯一協調器決定是否查詢；同碼正常刷新仍可執行。
- 同頁多元件要分開持有狀態：不同容器各有在途請求與操作鎖；同容器重新 mount 必須終結前 owner。只依容器重新查 DOM 的舊閉包，會直接取得新元件節點。（src/upload.js:92–105）

## (b) 驗收矩陣修正（U3、U5 與未鎖排程的 U4／U6／U8 會假通過）
| 列 | 定稿操作與必要斷言 |
|---|---|
| U1 | 改碼與 reload() 放同一次 page.evaluate()，先凍結輪詢；從改碼前開始計數，核對 B 的 code＋prefix，B 的 mine 恰 1 次 |
| U2 | 獨立初始化 A 有題，直接 A→B，B 尚扣住時就斷言 A 消失；B 失敗仍空白＋提示；B 之後成功顯示 B。另參數化 B 為 null／""：不得發請求 |
| U3 | 不換家庭：扣國語查詢→stop→同容器掛數學並顯示→放行國語。數學卡片及提示不變；舊 handle 的 reload() 不發請求 |
| U4 | 舊 A 保持未結束，在期限前連做三次 reload(true)，每次完成新請求再做下一次；逐次核對請求及目標狀態 |
| U5（採 (d) 後改）| 連續 reload 只發一筆；該筆失敗釋放後可重查 |
| U6 | 扣住刷新 B→撤回成功→先斷言 X 消失→才放行舊 A；再測 B 失敗及 B 仍含 X，X 均不回來 |
| U7 | 撤回 abort／永不返回至期限＋遲到成功／done／not-found：恢復操作、不自動重送、遲到 callback 不冒成功 |
| U8 | 注入可控 Date.now()／timer：時間超過期限但 timeout 尚未執行→先放行 A；A 不得採用。另讓 abort 無效果，期限後仍須能發新查詢 |
| U9 完整 stop | 分別扣住 mine、撤回、縮圖、upload→stop 兩次→同碼重掛、填新草稿→放行舊操作及確認 timer → 新畫面／草稿不變，舊元件零新增請求 |
| U10 撤回途中換家庭 | A 撤回扣住→切 B→B 撤回 Y 扣住→放行 A 成功／失敗 → 不顯示 A 訊息、不解除 Y 的鎖；另測 A→B→A、換碼後立即點舊確認鈕，均不得沿用舊操作 |
| U11 上傳途中換家庭 | 選兩張→扣第一張→切 B→放行第一張 → 第二張不送、不改送 B、不清 B 草稿；另扣在縮圖階段再換碼 → 零 upload POST；已送出的結果不得宣稱取消成功 |
| U12 同頁多元件 | 同掛國語、數學→扣國語→完成數學→stop 國語→刷新數學 → 數學照常更新、互不覆蓋；同科雙容器也跑一次 |
| U13 舊收尾不清新鎖 | 舊 A→撤回成功→扣新 B→讓 A 逾時／失敗→reload(true) → B 在途時不多發；B 完成後可再查 |
| U14 重畫與連續撤回 | 扣撤回 X→完成 mine 造成重畫→嘗試撤回 Y → 零第二筆 POST；X 成功後扣刷新→撤回 Y 成功→放行含 Y 的舊刷新 → X、Y 不重現 |
| U15 回應有效性 | 已有清單→分別回 HTTP 500＋ok:true、非法 JSON、ok:false、items:null／{}→再正常成功 → 失敗保留清單、不更新成功狀態；後續恢復（post() 目前不檢查 HTTP，且先寫 APPLIED／LAST 才 render）|

## (c) 數字
- 90 秒可暫留（未實測的設計值）；期限涵蓋 fetch、本文與解析；回應、發送、回前景時都檢查 deadline；先邏輯結束再 abort。
- 兩秒輪詢只當補救。首選同步碼寫入端發出變更事件／訂閱通知，搭配跨頁 storage、visibilitychange／pageshow；每個操作入口仍重讀家庭碼。僅輪詢無法辨認兩次檢查間的 A→B→A。

## (d) 推薦：每元件單一有效在途 mine＋期限＋AbortController＋操作身分檢查（取代 B 的併發 Map）
假設：需要刷新，不需要同世代手動併發查詢（reload 定位為「打開時重抓」）。
1. 同家庭、同世代已有查詢，手動與自動刷新都合併等待，不取消再重開。
2. 換家庭、撤回成功、上傳成功使舊查詢失效；先釋放自己的 slot，再 abort，按需要開新查詢。
3. 回應須同時符合 owner、家庭 revision、查詢世代、期限；舊 finally 只有在 ACTIVE === req 時才能清 slot。
4. 撤回成功即本機移除並保留過濾集合；撤回、上傳另持 operation token，stop 同步終結所有操作資格。
可移除 SEQ／APPLIED／PENDING Map。AbortController 只是節省資源，正確性必須在 abort 無效時仍成立。
