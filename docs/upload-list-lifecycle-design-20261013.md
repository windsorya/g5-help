# 補題區清單查詢生命週期（src/upload.js）：設計（2026-10-13，升級階梯）

## 為什麼升級
upload.js 的「你補的題目」清單連 3 輪審查 FAIL（8601526 → 954df2a → 1a9b918），1a9b918 的三項有兩項是上一輪修法自己引入：
- `reload()` 先 `codeCheck()`（內含 `load()`）再 `load()`，一次換碼發兩次查詢；後發的先失敗、先發的成功被序號規則丟掉，畫面空白。
- `stop()` 沒移除 storage 監聽；同容器重掛別科元件後，已停止的舊元件被喚醒，把舊科目清單蓋上去。
- 「換家庭查詢失敗」測試先停止同步再換家庭，直接 A→B 有沒有清空根本沒測到。

## 根因（沿用同日難題站 99b8394 的設計者結論，見 docs/withdraw-poll-design-codex-designer-20261013.md）
缺少「每個查詢各自持有世代、家庭碼、採用資格及釋放期限」的完整生命週期；upload.js 的查詢與撤回本來就是從難題站抄來的同一結構，所以同一個病。
upload.js 另多一層：元件可以被 stop／重掛，舊元件的計時器與監聽必須一起結束。

## 採用：設計者選項 B（請求紀錄按世代隔離＋成功序號單調＋每筆逾時）＋ C 的「撤回成功當下本機移除」，再加三條
狀態（每個掛載的元件各自一份）：
- `FAMILY`：目前家庭碼（掛載時讀；之後只由 familyCheck() 改）
- `EPOCH`：撤回成功或換家庭才遞增；`SEQ` 全元件遞增不歸零；`APPLIED`：本世代最後成功套用的序號
- `PENDING`：seq → {seq, epoch, family, timer, closed}；`WITHDRAWN`：本家庭已確認撤回的 ID（換家庭清空）
- `WD_PENDING`：撤回中（同時最多一筆；記發出時的家庭碼）；`STOPPED`：元件已停止

規則：
1. **單一查詢入口** `load(auto)`：先 `familyCheck()`；家庭碼沒變就不另發；`auto` 只在「本世代、本家庭、尚未結束」的查詢存在時略過（舊世代不擋輪詢）。`reload()` 只呼叫一次 `load()`。
2. **familyCheck()**：家庭碼一變（同頁停止同步、換家庭、別的分頁改）⇒ `FAMILY` 換新、`EPOCH++`、`APPLIED=0`、`LAST=null`、`WITHDRAWN` 清空、撤回確認取消，立刻重畫（清單空白）；有新碼才查一次。每 2 秒比一次＋storage 事件（同頁 `G5Sync.stop()` 不發 storage 事件）。
3. **每筆查詢都走同一個 finish(req, outcome)**：已結束就返回；標記結束、清計時器、只刪自己這筆；元件已停止、家庭碼或世代不符 ⇒ 不碰畫面。成功且 `seq > APPLIED` 才套用（濾掉 withdrawn 與 `WITHDRAWN`）；失敗不推進 `APPLIED`、保留 `LAST`，只有還沒被較新成功超越時才顯示「進度暫時讀不到」。
4. **逾時 90 秒**（設計值：高於審查反例的 65 秒，容許跨過一次 60 秒輪詢；不是實測 GAS 延遲）：到期先 finish 釋放，再嘗試 abort。
5. **撤回**：送出時建 `WD_PENDING`、所有撤回鈕停用（重畫也保持停用）；只有明確 `ok:true` 且家庭碼未變才：加入 `WITHDRAWN`、`EPOCH++`、`APPLIED=0`、從 `LAST` 移除並立即重畫、再發新世代查詢。明確失敗（done／not-found／其他）不移除、顯示原因。網路失敗或逾時：不移除、顯示「撤回結果尚未確認，請重新查詢。」，不自動重送。
6. **stop()**：`STOPPED=true`、清掉所有 interval／timeout、移除 storage 監聽、所有在途查詢與撤回標記結束；之後任何遲到回應都不碰畫面。
7. 卡片加 `data-mine-id`，測試精確定位。

## 有限驗收矩陣（先寫成 tests/e2e_upload.py，Chromium＋WebKit）
| 案例 | 操作 | 預期 |
|---|---|---|
| U1 換碼後 reload 只查一次 | A 家庭清單顯示 → 改成 B → 呼叫 `reload()` | B 的 mine 請求恰 1 次 |
| U2 直接 A→B | A 清單有題 → 直接改成 B（扣住 B 的查詢） | 3 秒內 A 的題目消失；B 失敗 ⇒ 仍空白＋讀取失敗提示；B 之後成功 ⇒ 顯示 B 的題目 |
| U3 stop 後重掛 | 國語元件扣住查詢 → stop → 同容器掛數學元件 → 換家庭並觸發 storage → 放行國語的舊回應 | 數學清單不被國語題目覆蓋；已停止元件不再發請求 |
| U4 舊世代不擋輪詢 | 扣住 A → 撤回 X 成功 → 新查詢完成 → 連做 3 次 `reload(true)`，每次放行 | 每次都真的發出新查詢 |
| U5 較新失敗、較舊成功 | 扣住 A、B → B 失敗 → A 成功（帶新狀態） | A 套用、讀取失敗提示清掉 |
| U6 撤回後舊成功晚到 | 扣住含 X 的 A → 撤回 X 成功 | X 當下消失；放行 A 後 X 不回來 |
| U7 撤回網路失敗 | 撤回請求 abort | X 留著、顯示「撤回結果尚未確認」、按鈕恢復、沒有第二次撤回 POST |
| U8 查詢逾時 | 用假時鐘扣住 A、推進 91 秒 | 釋放並顯示讀取失敗、保留舊清單；下一次輪詢會再發 |
既有案例（沒開同步、兩張照片、送出鎖輸入、部分失敗、同頁停止同步）照舊保留。
